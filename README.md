# AI文字起こし・校正・議事録 PWA（Soundcore対応・無料で使える）

Soundcore Work などで録音した **MP3 を Android の共有シートからそのまま受け取り**、文字起こし → 誤認識の確認 → 整文 → 議事録・要約までを、**スマートフォン 1 台・課金なし・サーバーなし**で行うための PWA（ホーム画面に入れて使うWebアプリ）です。

> **動作確認の範囲（正直な報告）**
> - 自動テスト（server 43件・web 107件）と、実ブラウザ(Chromium)での検証（共有POST→Service Worker→取り込み、**実際の Whisper(tiny) モデルによる端末内文字起こし**、サブパス配信、オフライン）は確認済みです。
> - **未確認**：Soundcore Work 実機、Android 実機の共有シートへの表示、実際の日本語音声での精度、Gemini の実API（キーが無いためモックのみ）、WebGPU高速化。「コード上は対応、Soundcore Work 実機確認は未実施」です。

## 無料で使う（クイックスタート）

アプリは**静的ファイルだけ**なので、GitHub Pages（無料）で公開できます。サーバー・API課金は不要です。

### A. 公開する（最初に1回だけ。パソコンのブラウザで）
1. このリポジトリの変更を **main ブランチにマージ**する（`.github/workflows/pages.yml` が動くのは main への push のときだけです）。
2. GitHub のリポジトリ → **Settings → Pages → Build and deployment → Source を「GitHub Actions」**にする。
3. **Actions** タブで「Deploy to GitHub Pages」が緑になるのを待つ（数分）。
4. 公開URL（通常 `https://<ユーザー名>.github.io/soundcore-transcript-pwa/`）が発行されます。

> 注意：公開URLは誰でも開けますが、アプリは何も送信せず、データはあなたの端末の中にだけ保存されます（Gemini方式を選ぶ場合のみ、自分のキーで Google へ送信）。

### B. スマホに入れる（Android）
1. **Android の Chrome** で公開URLを開く。
2. ホーム画面の案内の「アプリをインストール」を押す（または Chrome メニュー︙ →「アプリをインストール」）。
3. ホーム画面に「議事録AI」ができます。**共有シートに出るのはインストール後のみ**です。

### C. 使う
Soundcore アプリで「音声をエクスポート」→ **MP3** → 共有先で「**議事録AI**」→ 内容確認 →「**文字起こしを開始**」。詳しくは [使い方](#使い方)。

## 3つの方式（無料の範囲）

「設定」画面で、文字起こしと、整文・議事録の方式を別々に選べます。

| 方式 | 文字起こし | 整文・議事録・要約 | 費用 | 音声/文章の送信先 |
|---|---|---|---|---|
| **端末内（標準）** | 端末内 Whisper（transformers.js + ONNX/WASM） | 簡易（ルールベース・AIなし） | 無料 | **外部へ送信されません** |
| **Google Gemini** | Gemini（音声を直接文字起こし） | Gemini（整文・校正候補・議事録など高品質） | 無料枠の範囲 | **Googleへ送信**（下記注意） |
| 自前サーバー | サーバー経由 OpenAI | 同左 | 従量課金 | サーバー→OpenAI（上級者向け） |

### 端末内（標準）
- 初回のみ、モデル（tiny 約41MB / **base 約77MB（既定）** / small 約249MB）と実行エンジン（約27MB）を Hugging Face / 自サイトから**ダウンロード**します。**Wi-Fi 推奨**。設定画面から事前にダウンロードでき、以降はオフラインでも動きます。
- 速度の目安（実測）：サーバー用PCのCPU（単一スレッドWASM）で base は **音声の約0.45倍の時間**（13秒の音声を5.8秒）。**スマホはこれより遅い可能性が高く**、長い会議では録音時間の数倍かかり得ます。処理中は**画面を開いたまま**にしてください（対応ブラウザでは画面を消さないよう要求します）。
- **上限は45分**（デコード後の音声がメモリを使うため）。超える場合は理由を表示し、Gemini への切替を案内します。
- 精度：Whisper の日本語精度は、専門用語・雑音・複数人の会話で落ちます。**実際の日本語音声での精度は未検証**です。専門用語辞書と誤認識確認で補ってください。無音区間は幻覚（存在しない文）防止のためモデルに渡さず、同じ文のループは自動で1つにまとめます。
- 簡易整文・簡易抽出はAIではありません。言い淀み（えー・あのー等）の除去、重複の整理、原文の文の**抜き出し**（要約・決定事項・ToDo・議事録の見出し構成）のみで、**入力に無い内容は作りません**。画面にも「ルールベースの簡易版」と明示します。

### Google Gemini（無料枠）
1. Google AI Studio（https://aistudio.google.com/apikey）で **自分のAPIキーを作成**する。
   - 課金（Billing）設定は**有効にしないでください**（無料枠の範囲で使います）。クレジットカード登録が必要かどうかは、画面の案内に従ってください（公式ドキュメントでは確認できませんでした）。
   - 可能なら、キーに「HTTPリファラー制限（公開URL）」を付けてください（Google は、クライアントアプリのキーには制限をかけることを推奨しています）。
2. アプリの「設定」→ 方式で Gemini を選び、**キーを入力して「保存して接続テスト」**。
- **⚠ 重要（プライバシー）**：Google の公式料金表では、**無料枠は入力内容が Google の製品改善に使われる**（EEA・スイス・英国を除く）とされています。**機密性の高い会議・個人情報を含む音声には使わないでください。** 所属組織の規程や関係者の同意を確認してください。
- キーはこの端末の IndexedDB にのみ保存されます（バンドル・リポジトリ・ログ・バックアップに含まれません）。Google は「Webアプリにキーを埋め込まない」ことを求めており、本アプリはキーを埋め込まず**利用者自身が自分の端末に入力する**方式です。端末を他人に渡す場合はキーを削除してください。
- 無料枠には回数・量の上限があります（429エラー時は待って再試行。上限値は変わるため [Googleのレート制限ページ](https://ai.google.dev/gemini-api/docs/rate-limits) / AI Studio で確認）。長い音声は20分ごとの時間範囲に分けて順に処理し、Googleに一時保存したファイルは処理後に削除します（失敗時も削除を試みます）。
- 既定モデルは公式ドキュメントで「新規プロジェクトに推奨」とされていた `gemini-3.8-flash`。設定画面で変更できます（モデル名は変わるため、動かない場合は公式の最新を確認）。
- 実APIでの動作は**未確認**です（キーが無いため、リクエスト形式を公式ドキュメントに合わせ、モックでテスト）。

## 使い方

1. Soundcore Work で録音 →「音声をエクスポート」→ **MP3**。
2. 共有シートで **「議事録AI」**（出ない場合はアプリを開いて「**MP3を選択**」）。
3. **確認画面**：ファイル名・サイズ・長さ・形式を確認。外部送信の有無の注意が出ます。**「文字起こしを開始」を押すまで何も始まりません**（誤共有で処理されません）。
4. **文字起こし** → 生文字起こしが表示される。
5. **確認・校正**：AIまたは辞書が「誤認識の候補」（原文・候補・理由・確信度）を出す。**採用／却下／自分で修正**はあなたが決めます。確認済みにすると別データとして保存。
6. **整文** → 差分（確認済み→整文）を確認。
7. **議事録・要約・箇条書き・決定事項・ToDo・報告台本**を生成。コピー／Markdownコピー／TXT・MD保存／共有。
8. 履歴・専門用語辞書（誤認識→正式表記も登録可）・設定（JSONバックアップ）。

> Soundcore Work が実際に送る MIME type は公開情報では確定できないため、`audio/mpeg`・`audio/mp3`・`audio/*`・`.mp3`・`application/octet-stream` などを受け入れ、受信後に**先頭バイトで実体を検証**します。設定の「開発者モード」で、受信した MIME type・ファイル名・サイズを確認できます。

## アーキテクチャ

npm workspaces の monorepo です。

```
shared/   フロント/バック共通の型・定数・LLM共通プロンプト（創作禁止ルール）
web/      React + TypeScript + Vite の PWA（これだけで完結。GitHub Pagesで公開）
server/   任意：自前サーバー方式（Fastify + ffmpeg + OpenAI）
scripts/  アイコン生成 / PWA実ブラウザ検証 / 端末内Whisper検証
```

**エンジン構成（`web/src/lib/engines/`）**：処理を差し替え可能な「エンジン」に分離しています。

| ファイル | 役割 |
|---|---|
| `types.ts` | `TranscribeEngine` / `TextEngine` インターフェース |
| `local.ts` / `whisper.worker.ts` / `whisperCore.ts` | 端末内Whisper（Web Worker、無音スキップ、静かな点での区間分割、時刻見出し） |
| `gemini.ts` | Gemini REST（Files API、20分ごとの時間範囲、再試行、キーはヘッダのみ） |
| `rules.ts` | AIなしの簡易整文・抽出 |
| `server.ts` | 自前サーバー（上級者向け） |
| `notices.ts` | 方式ごとのプライバシー注意文 |

`web/src/lib/pipeline.ts` が、選択中のエンジン経由で各段階を実行し、二重実行防止・完了段階の再実行抑止・生データ不変を保ちます。

**選定理由**：サーバーを持たない構成にすることで、**課金・運用コスト・サーバーへの音声送信をゼロ**にできます。共有受信は Service Worker が処理するため、静的ホスティングでも成立します。依存は最小限（React、`idb`、`diff`、`@huggingface/transformers`）。

## PWA と Web Share Target の仕組み

`web/vite.config.ts` の manifest に `share_target`（POST + multipart/form-data、`audio/mpeg`・`audio/mp3`・`audio/*`・`.mp3`・`octet-stream` を受理）を定義。配信パス（`/` または `/<リポジトリ名>/`）は `VITE_BASE` で切り替わり、`start_url` / `scope` / `share_target.action` / Service Worker がすべて連動します。

```
Android共有シート → POST <base>share-target (multipart)
 → Service Worker が横取り（src/sw.ts → handleShare）
 → File を IndexedDB「shareInbox」へランダムIDで一時保存
 → 303 See Other で「<base>?share=<id>」へ（更新が POST 再送にならない）
 → React が share=<id> を検出 → 先に URL から消す
 → 受信箱から取り出して取り込み（成功・失敗とも受信箱の行を削除）
 → 確認画面（#/r/<id>）
```

- **二重登録・再処理防止**：URLから先に消す／消費後に削除／内容指紋（サイズ+先頭・中央・末尾2MBのSHA-256）で同一音声を検知。24時間超の残骸は起動時とSW activate時に削除。
- **更新対策**：プリキャッシュはrevision付き・旧キャッシュ自動削除。新SWは待機し「更新する」を押したときだけ有効化（処理中の強制リロード防止）。`/api` と `/share-target` はキャッシュしない。
- **オフライン**：アプリシェル・履歴・（ダウンロード済みなら）端末内文字起こしが動作。

## データの扱い（4種類を混ぜない）

| 種別 | 保存場所 | 説明 |
|---|---|---|
| ① 生文字起こし | `record.rawTranscript` | 音声認識の出力。**一度保存したら変更不可**（DB層で強制） |
| ② 確認済み文字起こし | `record.confirmedTranscript` | 採用/却下/手修正を反映した、あなたが確定した版 |
| ③ 整文 | `record.polished` | ②から生成。①②は上書きされない |
| ④ 生成物 | `record.outputs.*` | 議事録・要約・箇条書き・決定事項・ToDo・報告台本（各々別データ） |

保存はすべて端末のIndexedDB（履歴・辞書・設定・音声）。JSONバックアップ（音声・Geminiキー・トークンは含まない／既存データは上書きしない）。

## 開発（ローカル起動・テスト・ビルド）

要件: Node.js 22.9 以上、（server のテストのみ）ffmpeg / ffprobe。

```bash
npm ci
npm run dev:web                       # http://localhost:5173（SWはdevでは無効）
npm run lint && npm run typecheck && npm test
npm run build                         # web/dist と server/dist
VITE_BASE=/soundcore-transcript-pwa/ npm run build -w @app/web   # Pages用ビルド
npm run verify:pwa                    # 要build。Chromiumで manifest/SW/共有POST/オフライン、サーバーモードとPagesモード
VERIFY_LOCAL=1 npm run verify:pwa     # さらに実Whisper(tiny)で端末内文字起こしまで検証（要ネットワーク）
node scripts/verify-whisper.mjs <音声> tiny english   # 端末内Whisperワーカー単体の検証
```

`.npmrc` で `ignore-scripts=true` にしています（`onnxruntime-node` のインストールスクリプトがネットワークからバイナリを取得して失敗しうるため。ブラウザでは使いません）。

## 上級者向け：自前サーバー方式

サーバー（Node + ffmpeg）を自分で運用し、OpenAI API（従量課金）で処理する構成です。**課金が発生します。** 無料で使う場合は不要です。

- アプリをサーバーから配信した場合のみ、設定に「自前サーバー」方式が表示されます。
- 環境変数は `.env.example` を参照（`OPENAI_API_KEY` は**サーバー側のみ**、`APP_ACCESS_TOKEN` 必須）。`docker build` / `docker compose up`、`npm start`。
- 長時間音声は ffmpeg で圧縮→無音点で分割→順次文字起こし→結合。一部失敗は失敗区間のみ再試行。一時ファイルは処理後・エラー時・起動時・TTL経過時に削除。
- OpenAI のモデルは公式ドキュメント（2026-10確認）：文字起こし `gpt-transcribe`（25MB/リクエスト）、LLM `gpt-6.1-sol` / `gpt-6-luna`。`gpt-transcribe` の `keywords` 送信形式は公式に明記が見当たらず**未検証**（400時は付与なしで1回再試行）。

## プライバシー
- **端末内方式**：音声・文章は端末の外へ出ません（初回のモデル取得で Hugging Face と通信するのみ。音声は送られません）。
- **Gemini方式**：音声（文字起こし時）と文章（整文・議事録時）が Google へ送信されます。無料枠は製品改善に使われる場合があります。画面に注意文を表示します。
- **自前サーバー方式**：「外部AIサービスへ音声を送信します。利用する音声について、所属組織の規程や関係者の同意等を確認してください。」を表示。サーバー上の一時保存は処理目的のみで、成功時・エラー時・起動時・TTL後に削除します。
- 端末側：履歴・辞書・音声は IndexedDB のみ。音声は「音声を削除」で明示削除でき、既定では文字起こし完了後に自動削除。
- 外部通信は、選んだ方式の送信先と、端末内方式の初回モデル取得（Hugging Face）のみ。CDN・解析・外部フォントは使いません（onnxruntime のwasmも自サイトから配信）。

## 現在の制限事項
- Soundcore Work 実機・Android 共有シート・実日本語音声の精度・Gemini実API・WebGPU高速化は**未確認**。
- 端末内：**45分まで**。スマホでは遅い可能性（長時間はGemini推奨）。実行中は画面を開いたままにする必要がある（バックグラウンドでは止まることがある）。処理のキャンセルや途中再開は未対応。区間（約2.5分）単位の進捗。話者分離なし。時刻は区間単位。
- 簡易（ルールベース）の整文・議事録は、原文の抜き出しと整形のみ。自然な文章への書き換え・正確な議題判定はできません。AI候補の誤認識抽出はできません（辞書候補のみ）。
- Gemini：無料枠の回数・量の制限と学習利用。一部区間で失敗した場合は最初からのやり直し（アップロードした音声は削除される）。実キーでの形式は未検証。
- 共有受信はインストール済みPWA + Android Chrome のみ（iPhoneは非対応）。
- ブラウザの「サイトデータ削除」で履歴・モデルが消えます。バックアップを取ってください。
